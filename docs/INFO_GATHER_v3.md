## 0. ねらい【人間】
- テーマは「情報が多すぎる施主の状況」。いまの画面は読む作業が中心。**順位をつける、保存する、選ぶ**という手の動きで、情報に囲まれる感じと、そこから2社に絞る感じを体験させる
- 実際の施主の動きにも近い（チラシやWebを見比べる → SNSで検索して保存する → 見学の予約をする）

## 1. 流れ
1. 分譲地のカードから「家づくりをはじめる ▶」→ **全画面のシートがポップして、4社のチラシ・ウェブサイト**
2. **見比べて1位・2位・3位をつける**：4社のカードを2×2で大きく並べる（会社の印と社名、家の絵、キャッチ1行、性能のアイコン3〜4個、本体価格、注意書き1行。0-4 の中身）。カードを押した順に「1」「2」「3」の札が付く（押し直すと外れる）。「くわしく見る ＋」で、そのカードだけ1画面に大きく（カルーセル）
3. 3位までつけたら「SNSも見てみる ▶」→ 同じシートの中で **SNSの画面**（スマホの形の枠）
4. **検索ワードのタブが3つ**（`#注文住宅 後悔`／`#高断熱の家`／`#ローコスト住宅`）。各タブに投稿4つ。気になる投稿を**各タブで1〜2個「保存」**（しおりの印。押すと墨に塗られて小さく弾む）。合計3〜6個
5. 3つのタブで保存できたら「見に行く会社を選ぶ ▶」→ シートが閉じる
6. **見に行く2社を選ぶ画面**：4社の札が並び、チラシで1位・2位をつけた2社が**最初から選ばれている**（変えてよい）。画面の端に、集めた情報のメモ（チラシの順位、保存した投稿を会社ごとに小さくまとめたもの）。「この2社を訪ねる ▶」で1社目の打ち合わせへ
7. 次へ進むと、メモは**そっと消える**（短いフェード）。要望の記憶にもエンジンにも入れない（担当者に明示的な要望として伝わったわけではないため）

## 2. データ
- チラシ：`standard_specs.json`（`chirashiIcons` と仕様）とエンジンの本体価格。D工務店は「地元で40年」
- SNS：`data/content/sns_search.json`（新規。3つの検索ワード × 投稿4つ。会社の名前が出るもの・出ないもの、良い話・気になる話・食い違う話が混ざる。価格の数字は書かない）
- これまでの入口（展示場・見学会・口コミ・比較記事）の文は、使わない（`info_sources.json` は残すが、この画面では読まない）。展示場や見学会の体験は、SNSの投稿の中に入れてある
- 記録：チラシの順位と保存した投稿は、出来事の記録（イベント）には残す（あとで振り返りやレポートに使うかは人間が決める。いまは使わない）

## 3. 画面の決まり
- シートは全画面（下からせり上がる、0.3秒）。上に「1／2 チラシを見比べる」「2／2 SNSを見る」の進み具合
- いまやること（進行の帯の左）：「気になる順に、1位から3位まで押してみましょう」→「各タブで、気になる投稿を1〜2個保存しましょう」→「見に行く会社を2つ選びましょう」
- 字はチラシのキャッチ28px以上、投稿は20px以上
- ひとりプレイでは、パートナーのAIのひとこと（「わたしはCデザインが気になるな」）を1回だけ吹き出しで出してもよい。決めるのはプレイヤー
- 動きを減らす設定では、せり上がりと弾みを止める

## 4. 受け入れ基準
- [ ] 「家づくりをはじめる ▶」のあと、全画面のシートで4社のチラシが2×2で大きく並び、押した順に1・2・3の札が付く
- [ ] SNSの画面に3つの検索ワードのタブと投稿があり、各タブで1〜2個保存できる
- [ ] シートが閉じると、2社を選ぶ画面で、チラシの1位・2位の会社が最初から選ばれている
- [ ] 集めた情報のメモが、選ぶ画面にだけ出て、次へ進むと消える。担当者の会話や要望の記憶に、保存した投稿の中身が出てこない
- [ ] チラシと投稿の内容が、標準仕様の表と食い違わない（価格・年数・性能）
