## 1. モデルの使い分け
- 役割ごとに、実際に呼んでいるモデル名（API のモデル文字列）と、その設定がある場所（ファイルと行）
  - 担当者の会話／担当者の提案（計画役）／自分のAI（パートナー）／要望の読み替え／レポートの文／概略の世界・SNS／研修のお客さま役／研修の審査役
- 1プレイあたりの Claude の呼び出し回数の目安（記録やログから。数えられなければ「未確認」）
- 構造化出力（JSON）と検証の仕組み：検証に落ちたときの処理、数字の枠（型つきの差し込み）の照合のしかた

## 2. 開発で使った Claude の機能
それぞれ「使った／使っていない」と、使ったなら証拠（ファイル・コミット・ログ）：
- Skills（`.claude/skills/` の各スキルの名前と、実際に走らせた回数や結果のファイル）
- サブエージェント（Agent ツールで別のエージェントを立てたことがあるか。あれば何の作業か）
- MCP（使ったサーバーの名前と用途）
- フック（`.claude/settings*.json` などに設定があるか）
- CLAUDE.md による決まりごとの共有
- 複数の Claude Code セッションでの分担（実装と動画）

## 3. 仕組みの事実
- 計算エンジン（金額・日数を出すコード）の場所と、Claude が数字を作らないことを保証している所
- 出来事の記録（イベントソーシング）とスナップショットの実装場所
- テストの数と、いま全部通るか
- 公開の構成：Cloudflare Workers、APIキーがブラウザに出ないこと、1人あたりの回数制限、費用の上限
- 担当者の研修：回数（ラウンド数）、お客さまの人数、評価の項目、改善の前後の数字（例：決まり文句 92→2、「答えたか」1.58→2.67）と、そのログのファイル

## 4. 試行錯誤の量（数えられるものだけ）

- 作り直した主な画面や仕組みの数（指示書の版：FLOW v3、HEARING v2、REPORT v2 など）
