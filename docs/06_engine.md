## 1. 大原則（v0.2）

1. **数字はClaudeに作らせない。** 金額・日数・面積・体験の段階は、すべてエンジンが出す
2. **世界の事実と、知っていることを分ける。** エンジンは事実を知っている。プレイヤーと担当者は、知っている範囲しか知らない【B】
3. **台帳は1冊、層は3つ。** 仕様・数量 → 原価・価格（会社別）→ 見積の見せ方（会社別）【B】
4. **操作の履歴を記録の基本にする。** 一定の間隔で状態の写しも残す。Claudeの出力、モデル名、プロンプトの版も保存する【B】
5. **事前に説明しない**【人間】。ただし、次の3つを分けて扱う【B】（★1）

| 情報の種類 | 扱い |
| --- | --- |
| 判断の前提・契約の条件（例：外構を削ると舗装が減る、ローン特約の期限） | **聞けば答えてもらえる**（担当者や銀行に質問できる） |
| 起こりうるリスク（例：大開口は冬に冷えやすい） | **調べたり、専門家に聞いたりすれば推測できる**（担当者がひとこと言うこともある） |
| 実際に起こる具体的な出来事（例：2月の朝、足元が冷たい） | **1年後の再生で初めて明かす** |

## 2. 世界の構造

- **共通の初期条件**：家族、予算、土地（区画）、要望、外的な乱数（地盤、天候、親の口出しの種類など）は全世界で共通【B】
- **土地**：第2・第3希望の区画が当たる、から始める【人間】。全世界で同じ区画に建てる。土地の契約期限を逃した世界だけ、別の区画へ移る【B】
- **画面の16枠**：抽象化された16の敷地として並べる【人間】。これは「表示の枠」で、物理的な区画とは別の概念として扱う【B】（★2）
- **世界は消さない**：内部の世界の数に上限は設けない（ただし詳しく生成する数には上限を置く）。17本目以降の世界が生まれたら、画面の表示枠だけを入れ替える。非表示になった世界も残す【B】
- **詳しく動かす4世界**【人間】
  - プレイヤーの世界
  - 会社違いの世界：分かれ道1で最後まで迷ったもう1社の世界【A】
  - 予算・仕様違いの世界：分かれ道3か4で逆を選んだ世界【A】
  - 大きな出来事の世界：倒産か大幅な増額が起きる世界を1つ必ず入れる（デモの撮れ高のため）【A】
- **比べ方**：「1か所だけ違う」ではなく「1つの決断を起点に分かれた世界」として見せる。外的な乱数は共有し、選択から生まれた差だけを比べる【B】

## 3. 時計

| 時点 | 出来事 | v0.2での扱い |
| --- | --- | --- |
| 0日目 | 区画が当たる | 抽選の場面は出さない【人間】 |
| 0〜60日目 | 会社選び・プラン・見積 | 見積には精度の段階がある（下表） |
| 60日目 | 土地の契約期限 | 過ぎると区画を失い、別区画で仕切り直し（＋30日）。延長の交渉ができる場面を1回だけ置く【B】 |
| 土地契約＋30日 | ローン特約の期限 | 「期限の最終日、まだ銀行の返事が来ていない」場面を作り、条件を確かめる／延長を頼む／何もしない、を選ばせる【B】 |
| 土地契約＋60日 | 土地の決済 | **土地の代金の資金**（自己資金・土地先行融資・つなぎ融資）と、**最終的な住宅ローン**を分けて管理する【B】 |
| 決済＋14〜30日 | 着工 | |
| 着工＋45日前後 | 上棟 | |
| 着工＋90〜130日 | 完成・引き渡し | 型と混み具合で変わる |
| ＋365日 | 1年後 | 入居後は季節ごと |

**見積の精度と時間**（Cの工程の衝突の直し方）【B】

| 精度 | 中身 | かかる日数（仮） |
| --- | --- | --- |
| 概算 | 初回プランと同時の資金計画（坪単価ベース） | 0〜7日 |
| 契約判断用 | 主な仕様を入れた見積 | 14〜28日 |
| 詳細 | 仕様をほぼ決めた積算 | 42〜56日 |

- どの精度で契約するかは、会社の進め方の標準と、プレイヤーの判断で決まる。Cの標準は「詳細」だが、プレイヤーが頼めば「契約判断用」で土地の期限に間に合わせられる。その代わり、契約後に増える額の幅が大きくなる
- 精度を上げるほど時間を使う、というトレードオフを、プレイヤー自身の選択にする【B】

## 4. 世帯と家計

### 4-1. 世帯の型（v0.2）

- **初回は3つの家族から選ぶ**。名前は「堅実／標準／ゆとり」ではなく、暮らしの背景の短い文で見せる。2回目以降はランダムも選べる【B】（★3：v0.1の「ガチャ」【人間】からの変更）
- **住宅の規模を世帯に合わせる**。土地は共通のまま、延床面積の目標を世帯ごとに変えて、どの型にも選べる道が複数あるようにする【B】

| 項目 | 型1 | 型2 | 型3 |
| --- | --- | --- | --- |
| 暮らしの背景（例） | 共働き、子ども2人。予算を抑えながら、毎日の暮らしを良くしたい | 共働き、子ども2人。性能も間取りも、そこそこ欲張りたい | 共働き、子ども2人。将来の働き方の変化にも備えたい |
| 世帯年収（税込） | **680万**（620万から上げた） | 800万 | 980万 |
| 年間の手取り | 約520万 | 約610万 | 約740万 |
| うちボーナス（手取り） | 約80万 | 約110万 | 約140万 |
| **通常月の手取り** | （520−80）÷12 ≒ **36.7万** | （610−110）÷12 ≒ **41.7万** | （740−140）÷12 ≒ **50.0万** |
| 預金のうち家に入れる分 | 200万 | 350万 | 500万 |
| 預金のうち手元に残す分（生活防衛資金） | 150万 | 200万 | 250万 |
| 投資 | 50万 | 200万 | 400万 |
| 親の援助 | 0〜300万（条件付き、全世界共通の乱数） | 同左 | 同左 |
| 毎月の生活費（住居費を除く） | 24万 | 27万 | 31万 |
| 延床面積の目標 | 28〜31坪 | 31〜34坪 | 34〜38坪 |

- ボーナスは通常月に含めない（二重計上の修正）【B】

### 4-2. 借りられる額（審査金利3.5%、35年で計算した目安）

| | 型1（680万） | 型2（800万） | 型3（980万） |
| --- | --- | --- | --- |
| 審査の上限（返済負担率35%） | 約4,800万 | 約5,650万 | 約6,900万 |
| 参考：25%のライン | 約3,430万 | 約4,030万 | 約4,940万 |

- 審査金利3.5%は、金融機関共通の基準ではなく**ゲーム内の仮定**であることを、注記の範囲で扱う【B】
- 返済負担率は**審査と警告の指標**としてだけ使う。土地付注文住宅の利用者の平均は26.8%（2024年度フラット35利用者調査）【B】

### 4-3. 金利

- 変動 年1.2%、全期間固定 年3.8%をゲーム内の仮定として採用する（2026年10〜11月の報道の水準に合わせた）【B】
- 変動か固定かは、4つの分かれ道には入れず、契約の中の小さな判断にする【A】
- このままだと全員が変動を選ぶので、**変動の世界には1年後のレポートで「金利が上がったら」の一行を出す**（例：5年後に＋0.5%なら月々＋約1.2万）。P2の扱い【B】
- レビューAの「固定2.4%」案は、いまの市場の水準から離れるので採らない

### 4-4. ゆとりの出し方【B】

```
家計の余力（年）＝ 年間の手取り − 生活費 − 年間の住居費（返済＋固定資産税＋保険＋修繕の積立）− 教育・その他
ゆとりの段階 ＝ 余力の大きさで4段階（たっぷり／ほどよい／少し背伸び／きつい）
```

- 入居後1年の家計は、月ごとに計算する（ボーナス月は加算、外構の積み立てや投資の取り崩しもここで反映）【人間：予行演習の答え】

## 5. 台帳（3層）【B】

### 5-1. 層の構成

| 層 | 中身 |
| --- | --- |
| ① 仕様・数量 | 延床面積、窓の種類と枚数、設備、外構、工法、施工範囲、性能の等級 |
| ② 原価・価格（会社別） | 会社ごとの単価、値引き、付帯工事、施主支給、予備費、諸費用 |
| ③ 見積の見せ方（会社別） | 本体中心／総額中心／一式中心。どの項目を「別途」にするか、未確定の費用をどう書くか |

- 見積に載っていない金額も、エンジンの中には最初から存在する【B】
- 未確定の費用（地盤改良など）は、調査前の見積では「未確定／概算80〜150万」と幅で出す。調査で事実が判明したら確定する【B】

### 5-2. 型ごとの値（v0.2）

| 型 | 本体の坪単価（内部） | 見積の見せ方 | 地盤調査 | 断熱の標準 | 契約後の増額の傾向 |
| --- | --- | --- | --- | --- | --- |
| A：大手 | 95〜110万 | 本体中心。付帯・照明・外構・エアコンは「別途」 | 契約後 | **等級6** | 打ち合わせの回数しだいで大きくなりやすい |
| B：ローコスト／中堅 | 60〜70万 | 本体＋オプション表 | 契約後 | 等級5 | 標準仕様が最低限で、オプションが積み上がりやすい |
| C：作り込み型 | **80〜88万**（v0.1の90〜100万から下げた）【A】 | 総額（付帯・外構・諸費用込み）で見せるので、最初は一番高く見える | 契約前 | 等級6 | 精度の高い見積で契約すれば小さい |
| D：身軽型 | 70〜80万 | 一式（口約束が多い） | 曖昧 | 等級5 | 記録を取らないと、引き渡し時に追加請求の種 |

- 例：32坪で、Aの見積の表紙は約3,100万、Cの見積は付帯・外構・諸費用込みの総額で約3,950万。中身を比べると、Cの建物は実は適正価格、という現場の実感を再現する【A】
- 大手は性能・設備が高い。全国規模の高性能メーカーには、地元の会社が性能で勝てないこともある【人間】
- 倒産は型に固定しない。値引きの大きさ、前払いの比率、会社固有の財務の乱数で決める。大手でも起こりうる【人間】

### 5-3. 型と品質を分ける【B】

| 要素 | 型に紐づける | 世界ごとに変える |
| --- | --- | --- |
| 価格帯、標準仕様、提案の自由度、見積書の形式 | ○ | 一部 |
| 担当者の力量、説明の丁寧さ | | ○ |
| 工程管理の精度 | 一部 | ○ |
| 倒産のリスク | 会社固有の財務条件 | 一部 |
| 完成後の満足度 | | 家族との相性と、選択しだい |

- 同じAでも、担当者が優秀なら良い家が建つ。同じCでも、設計が良いことと、予算や工期を守れることは別【B】

### 5-4. 倒産したときの負担【B】

```
追加の負担 ＝ 前払いの超過額 ＋ 引き継ぎで増える費用 − 保証による補填（上限あり）
別に：工期の遅れ、仮住まいの費用
```

- 完成保証の適用は、会社の型ではなく、その世界の契約条件に紐づける。保証には対象と上限があることを、注記の範囲で扱う【B】

## 6. 敷地と面積【B】

- 次を別々の数値として持つ
  - 住宅本体の延床面積
  - 住宅本体の建築面積（1階の外形を基本とし、軒の出は簡略化）
  - カーポート・物置の建築面積（カーポートは一定条件で緩和がある。ゲームでは「緩和あり」の簡略値を使う）
  - 敷地の建蔽率60%・容積率150%【人間】
- 判定：本体の建築面積＋カーポート・物置の建築面積 ≦ 約109㎡
  - 例：1階25坪（約82.6㎡）＋カーポート2台＋物置 → 合計がおよそ117㎡で超過（1階の床面積が117㎡になるわけではない）
- 910グリッドの自動ゾーニングは提出後に回す。今回は延床・1階・建築面積の簡略モデルを先に作り、制約が発動することを確かめる【B】（★4）

## 7. 性能と暮らしの体験【A】【B】

- 内部で持つ値：断熱（等級5／6／7）、窓（標準／トリプル）、日射取得と日除け、暖房の方式と運転、気密（測定の有無と結果）、耐震（会社ごとの標準を基準に）
- **暖かさの体験**：内部の点数から4段階（寒い／やや寒い／おおむね快適／快適）を出す【B】
  - 点数の参考：基準 ＋ 断熱の段階（0〜2）×2.5 ＋ 窓（トリプル＋2）− 大開口・吹き抜け（−2.5）＋ 日射取得（＋0〜2）【A】
- 数字を出すのは1年後のレポートだけ。出すなら「外気温0℃・指定の暖房条件・朝の簡易モデル」の目安だと明記する【A】【B】
- 耐震：等級3を標準にしている会社もあるので、会社ごとの標準を基準に、追加費用と間取りへの制約を出す【B】
- 気密：「測定する」ことと「結果が良い」ことは別。測定の結果を受けて手直しする場面もある【B】
- **性能を上げれば必ず正解、にしない**：日除けや設備の計画が不適切なら快適性に問題が出る。広さを少し抑えて、性能や暮らしの質に回す、というトレードオフを作る【B】
- 数値を追っても、進め方しだいで子どもが「おうちは苦しくてきらい」と言うことがある【人間】

## 9. 分かれ道と自由な答え

- 4つの分かれ道の呼び方：だれと建てる？／なにを優先する？／いくらまでかける？／どう仕上げる？（v0.1のまま）
- **2択の生成**：Claude（上位）で1回ずつ
- **2択の検証**：機械的に確かめられることはコードで確かめる（実行できる行動か、資金は足りるか、契約済みのことをやり直そうとしていないか、存在しない会社を参照していないか）。「特定の会社を有利に描いていないか」のような意味の審査だけをClaudeが行い、それも重要な分かれ道と開発時のテストに絞る【B】（★5）
- **自由な答えの確定**【B】
  1. Claudeが入力を「変更の提案」に直す（例：`{借入:+60万, 窓:南の大開口をトリプル}`）。あわせて**選んだ理由**も抜き出す（決断の記憶）
  2. エンジンが仮計算する（価格・工程・資金・仕様）
  3. 条件を示す（増額、再審査、工期の変更）。判定は「できる／条件付き／確認が足りない／いまは難しい」の4つ
  4. 予算・契約・仕様の重要な変更だけ、プレイヤーが承認する。明らかに安全で戻せる行動は、そのまま反映する
  5. 状態を一括で更新し、出来事と差分を同時に記録する
- **後戻り**：1つ前の分かれ道まで。消費する日数は、場面と行動しだい（目安は＋14日）【A】【B】

## 10. 決断の記憶【B】

```json
{ "decisionId": "D03", "action": "外構を削る", "reason": "子どもの教育費を残したい",
  "priority": "家計の安心", "consequence": { "予算": "改善", "外構": "先送り" } }
```

- 理由は毎回は聞かない。入力文から推定できればClaudeが抜き出し、理由がわからない重要な場面だけ任意で聞く
- 1年後のレポートで使う。例：「あなたは庭の完成を後回しにしました。あのとき守ろうとしたのは、子どもの教育費でした。」
- Claudeは「失敗でした」と判定しない。本人が優先した価値観を言葉にする【B】

## 15. 人間に決めてほしいこと（★）

1. **情報の3段階**（1章の表）：「事前に説明しない」【人間】を、「判断の前提は聞けば答えてもらえる。具体的な出来事は再生で明かす」と解釈してよいか
