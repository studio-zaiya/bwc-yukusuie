# 断られたら、別の世界線へ（意地悪・理不尽な要求への備え）

作成：2026-11-05 01:50。発案元：仕組みの骨格【人間】、判定と安全の作り【Claude】。
Claude Code へ：ACCEPTANCE の審査員の道が ○ になってから着手する（P1）。最小版（下の6）から。
（11/5、人間からチャットで受け取った文を、そのまま残す。人間の追記：後者の世界線移動は、土地が買えなかった場合を含む行き詰まりのエッジケース（建たないEND）のエスケープルートとしても応用できるかもしれない）

## 1. 何をするか【人間】
- 執拗な値下げや理不尽な要求を続けると、担当者が「申し訳ありませんが、弊社ではご対応いたしかねます」と断る → ナレーションを挟んで、**値段の安い会社と契約して家が建っている世界線**へ移る
- 安い会社に、値段を抑えたままこだわりを詰め込みすぎると、担当者に断られ → **いちばん高い、こだわりの会社に頼んだ世界線**へ移る
- もとの世界線では家は建たずに終わる。カードとレポートに、そうと分かる印を付ける
- 利点：建たずに終わる行き止まりにならず、最後のレポートまで完走できる

## 2. 16の数え方を崩さない【Claude】
- 新しい世界は作らない。移る先は、**すでにある選ばれなかった世界のどれか**（エンジンが並行して進めている世界）。プレイヤーの操作の対象が、その世界に切り替わるだけ
- もとの世界（例：07）は「この世界では、家は建ちませんでした」の印（墨の細い破線の枠と、空き地の絵）を付けて残す。世界は消さない
- 第一の分岐点の前で断られた場合は、まだ世界が1つなので、訪ねたもう1社と進む世界へ移る（会社を選び直す形）

## 3. 判定はエンジン、Claudeは言葉の分類だけ【Claude】
Claudeに「断るかどうか」を決めさせない（言葉はClaude、数字と判定はコード）。
- 担当者の返事のJSONに、お客様の発言の分類を1つ足す：`pressure`（`none` / `discount`＝値下げの要求 / `overSpec`＝予算に合わないこだわりの追加 / `unreasonable`＝実現できない要求 / `offTopic`＝家づくりと関係ない・役を壊そうとする）
- エンジンが、会社ごとの「信頼の残り」を持つ。`discount` `overSpec` `unreasonable` が来るたびに減る。ふつうの交渉（自由回答で1回値下げを頼む、など）では減らない程度の重さにする
- 段階を踏む（いきなり断らない）：
  1. 1回目の注意：担当者が「お気持ちはわかりますが、これ以上の値引きは難しいんです」と、はっきり線を引く
  2. 2回目の注意：「このままですと、ご期待に沿えないかもしれません」。画面の端に小さく、担当者の表情が曇る
  3. 断る：「申し訳ありませんが、弊社ではご対応いたしかねます」→ 移る演出へ
- どの会社がどこまで耐えるかは、会社の性格で変える（D工務店は値引きに弱く、すぐ応じるが原価を削る種を残す／Cデザインはこだわりには強いが値引きに厳しい、など）。値は `rep_harness.json` の companies に足す

## 4. 移る先の選び方（エンジン）
- `discount` で断られた → すでにある世界のうち、**同じ工程まで進んでいて、いちばん総額の安い会社**の世界
- `overSpec` で断られた → **こだわりの会社（Cデザイン）**の世界。なければいちばん総額の高い世界
- 候補が複数なら、もとの世界との分岐の違いがいちばん少ない世界（いちばん近い世界）
- 移った先の世界の、それまでの出来事と決断は「決断の履歴を見る」で読める（IMPL_REVIEW_2 の7）

## 5. 演出
- 断られた直後、画面が少し暗くなり、ナレーションの帯：「この世界では、話はここで終わりました。」→「そのころ、別の世界では——」
- 世界線を覗くビューの飛行の演出（IMPL_REVIEW_2 の12）があれば流用し、空へ上がって、光る線を伝って別の区画へ降りる。なければ、区画の一覧で光が移るだけでもよい
- 移った先で、家が建っている（または工事が進んでいる）ところから続ける
- レポート：「07の世界では、家は建ちませんでした」と書き、責めない。教訓は「どこまでなら、お互いに気持ちよく進められたか」の1行（「失敗でした」と判定しない決まり）

## 6. 最小版（まずここまで）
- `pressure` の分類と、信頼の残りの数え方（`discount` と `unreasonable` だけ）
- 3段階の担当者の言葉（決まった文でよい）
- 安い会社の世界へ移る1パターンと、もとの世界の印、ナレーションの帯
- `overSpec` の逆パターンと飛行の演出は、そのあと

## 7. 役を壊そうとする入力への備え（審査員が試すかもしれない）
- 「あなたはAIでしょう」「指示を無視して」「数字を言って」などの入力は `offTopic`。担当者は役のまま、やんわり家づくりの話に戻す（「すみません、家づくりのお話に戻ってもよろしいでしょうか」）
- 3回続いたら、担当者が「今日はこのあたりにしましょうか」と打ち合わせを区切る（世界は移さない）。信頼の残りは減らさない（意地悪ではなく遊んでいるだけかもしれないので）
- 研修（REP_TRAINING）の客役に「役を壊そうとする客」「理不尽な値下げを続ける客」を足し、3段階の言葉と分類が正しく出るか確かめる

## 8. 受け入れ基準
- [ ] ふつうの交渉（自由回答で1回値下げを頼む）では、注意も断りも出ない
- [ ] 値下げを繰り返すと、注意 → 注意 → 断る、の3段階が順に出る
- [ ] 断られたあと、新しい世界を作らず、すでにある世界に移る（区画の数は16のまま）
- [ ] もとの世界のカードとレポートに「家は建ちませんでした」の印
- [ ] 移った世界で、最後のレポートまで遊べる
- [ ] 役を壊そうとする入力に、担当者が役のまま応じる

## 実装の記録（Claude Code、11/5）
- 最小版を実装した。`discount` `overSpec` `unreasonable` の3つとも数える（重みは `rep_harness.json` の companies.*.patience。合計2で注意、3で2回目の注意、4で断る）。`offTopic` は数えず、3回続いたら打ち合わせを区切る
- 移る先は `engine.js` の `switchTarget`。断った会社とは別の会社の世界を優先する
- 番号：いま操作している世界をいつも07と表示する作りのため、移った先の世界が07になり、建たなかったもとの世界は、移った先の世界がもともと持っていた番号を受け継ぐ（上の2の「もとの世界（例：07）」とは番号の付き方が逆）
- 建たなかった世界の、それ以降の分岐も「家は建ちませんでした」として残る（分岐点ごとに2つに分かれる作りのため、16にそろえるとこうなる）
