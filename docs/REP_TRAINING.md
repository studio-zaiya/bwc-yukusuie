# 担当者の研修（Claude同士のペアレビュー）

作成：2026-11-04 17:45。発案元：研修で担当者を磨くこと【人間】、仕組みの具体化【Claude】。
Claude Code へ：HEARING_v2.md の実装が ACCEPTANCE で ○ になってから着手する。研修のスクリプトは `tools/rep_training/` に一から書く（外部のコードは使わない）。

## 1. 目的
担当者（4社＋コーディネーター）の返事から、掘り下げすぎ、聞き返しで進まない、数字を作る、不自然さを減らす。直すのは `data/content/rep_harness.json`（共通の土台と会社ごとの差分）だけ。

## 2. 道具
- 担当者：`rep_harness.json` から組んだシステムプロンプト（本番と同じ組み立ての関数を使う）
- 客役：`data/training/customers.json` の8人。それぞれに `survey.json` の答えの一式を持たせる（seedで作る）
- 審査役：`data/training/rubric.json`。数えられる項目（文の数、質問の数、数字、聞き直し、禁止語）はコードで数え、Claudeには「感じ」の6項目だけ採点させる
- モデル：担当者は本番と同じ（Sonnet 5.5）。客役と審査役は Haiku 5.5 で足りる。1回の研修の上限を、環境変数で回数と費用の両方に設ける

## 3. 手順（1回の研修）
1. 会社×客役×場面（総括と追加の質問／提案の説明）で会話を作る。1本は担当者の発言6回まで。深く回すのは A と C（全員×全員）、B と D は客役4人
2. 自動の項目を数え、審査役に採点させる。不合格の会話と、`worstTurn`（いちばん悪い発言と、こう言えばよかった）を集める
3. 不合格の型ごとにまとめ、`rep_harness.json` を直す。直し方の順番：①behaviors の言い方を具体的に ②その場面の examples に良い例と悪い例を1組足す ③会社の差分（tone、quirk）を直す。validator で防げるものは、プロンプトではなくコードで防ぐ
4. もう一度回し、合格率を前と比べる。下がった項目があれば戻す
5. 結果を `docs/devlog.md` に1〜3行で（例：「研修2回目：A・Cの合格率 54% → 88%。聞き返しの型を examples に追加」）。会話の記録は `out/rep_training/` に置き、コミットしない

## 4. 合格の目安
- 自動の項目：数字と禁止語はゼロ。文の数と質問の数は、95%以上の発言で守る
- 感じの項目：尋問っぽさ2以下、ほかは4以上が、会話の80%以上
- 最後に人間が、AとCの会話を2本ずつ読む（研修で数字は上がったが、人が読むと変、を見逃さないため）

## 5. 動画の材料
研修の前後で同じ客役への返事を並べた画面（例：「玄関の近くかなあ」への返事の前と後）は、開発記録のパートに使える。研修の回数と合格率の推移を、1枚の小さなグラフにしておく。
