## P0　名前の入力と、ひとりプレイ【人間】

15. **夫婦の名前をプレイヤーが入力する**
    - いまは「かず」「ゆう」で固定になっている。遊び方の1枚目（「あなたは」）で、ふたりの呼び名を入力できるようにする。初期値は「かず」「ゆう」のまま（空欄なら初期値を使う）
    - 色と形（1人目＝橙■、2人目＝空色●）は名前に関係なく固定。画面・付箋・会話・レポートのすべてで、入力した呼び名を使う
    - 入力欄の近くに「ニックネームで入力してください」と添える（本名を入れさせない）。呼び名は記録には残すが、ほかの用途に使わない
16. **ひとりプレイのとき、パートナーをAIにできる**
    - 遊び方の1枚目で「ふたりで遊ぶ（交互に入力）」「ひとりで遊ぶ（パートナーはAI）」を選ぶ。**審査員はひとりで遊ぶことが多いと考えられるので、初期値は「ひとりで遊ぶ」**。タイトルの「打ち合わせを終えた家族で、続きから遊ぶ」も、ひとりプレイで始める
    - パートナーのAIは Sonnet 5.5 にハーネスとロールを与える（Opus は費用に見合う差が出にくいので、まずは Sonnet。役割ごとに環境変数で切り替え可能にしておく）
    - ロール：家族の設定から作る人格（価値観、こだわり、口ぐせ）。プレイヤーとは違う希望を持ち、ときどき意見がぶつかる。全部を決めてしまわない
    - 出番：担当者が「奥様は？」「ご主人は？」とパートナーに聞いたときに答える／分岐点のあとに「どうしてそっちにしたの？」と聞く（決断の理由を集める）／帰り道に「伝え忘れたこと、あった？」と聞く／ときどき感想や心配を一言
    - パートナーの発言から出た希望は、パートナーの色（■か●）の付箋になる
    - 発言は短く（2〜3文）。数字は言わない（金額や日数はエンジン）。会話の主導権はプレイヤーに残す
    - ふたりで遊ぶときは、いまの「話す人」の切り替えを使い、担当者の質問に合わせて自動で切り替える（IMPL_REVIEW_1 のA9）

## P0　設計担当との調整（面積・ゾーニング・予算を確定させる）【人間の案、Claudeが具体化】

17. **要望から間取りの骨組みと予算を出す役割を Opus 5.5 にし、予算超過からの調整を、その場の打ち合わせとして体験させる**
    - 置き場所：第一の分岐点で会社を決めたあと、**設計申込・詳細打ち合わせ**（第二の分岐点「なにを優先する？」の手前）。プラン提案の時点では2社とも「ラフな概算」を出し、ここで1社と深く詰める
    - 役割の分担（大原則「言葉はClaude、数字はコード」を守る）
      - Opus：要望の台帳から、部屋の一覧（用途・広さの段階・1階か2階か・隣り合わせたい部屋）と、形の仮定（総二階／部分二階／平屋に近い、屋根の形）を組む。広さは「4.5畳／6畳／8畳…」のような**決まった選択肢から選ぶ**だけで、面積や金額の数字は作らない
      - エンジン：部屋の一覧から延床・1階と2階の床面積・建築面積を出し、建蔽率・容積率を判定し、形の係数（基礎と屋根は建築面積、外壁は外周の長さで効く）で見積と月々の返済を出す
      - Opus はツール呼び出しでエンジンに仮計算させ、結果を見て組み直す（読み替え → 仮計算 → 条件 → 承認 → 確定、の取引と同じ流れ）
    - 体験の流れ
      1. 担当者「いただいた要望を全部入れると、こうなります」→ ゾーニング図（1階・2階の部屋の塊を、コードで描く）と、延床・総額・月々・希望との違い（P0の1）
      2. 多くの場合は予算や建蔽率を超える。担当者が調整の案を2〜3つ出す（例：2階を広げて総二階に近づける＝基礎と屋根が減って安くなる／客間を和室コーナーに縮める／収納をまとめる）。案ごとに、エンジンが出した差額と、暮らしで何が変わるかを1行で
      3. プレイヤーは案を選ぶか、自由に書く（「書斎はいらない」「子ども部屋は将来仕切る」など）。そのたびにゾーニング図と金額が動く
      4. 「この間取りの骨組みと予算で設計を進めます」で確定 → 第二の分岐点へ。第二の分岐点の2択は、この調整の中で残った対立（例：広さを守る／総二階に寄せて予算を守る）から作る
    - 調整の回数は最大3回。超えたら担当者が「いったん持ち帰って整理しましょう」とまとめ、いちばん近い案で確定する
    - 待ち時間：Opus の応答中は、ゾーニング図の骨組み（読み込み中の形）と、担当者の「図面に落としています…」を出す。初回の案は、帰り道の場面のあいだに先に計算を始めておく
    - 選ばなかった世界線の家も、同じエンジンで延床と形を持つ（家の絵の大きさと形に反映する）
    - モデル：この役割（`PLANNER_MODEL`）だけ Opus 5.5。環境変数で Sonnet に切り替えられるようにする。1プレイあたりの呼び出し回数とトークン数を記録し、デモ前に費用を確かめる
    - エンジンへの追加：部屋の広さの段階の表、廊下・階段の割り増し、形の係数、建蔽率による上限。P0の1の「30坪に縮小」も、この仕組みで扱う
