   - 「30坪に縮小」のような面積の変更は、エンジンで扱えるようにする（延床を変えると、建蔽率・見積・暖かさ・家計が連動して変わる）

   - 「あと3回答えると、帰宅できます」のような残りの回数の表示は**出さない**【人間】
   - 代わりに、聞くことが一通り終わったら、担当者が「今日はこのあたりにしましょうか。次回までにラフなプランをお持ちします」と区切り、そこで「打ち合わせを終える」のボタンが目立つ形で出る。それまでもボタンは小さく置いておく（早く進めたい人のため）
   - **打ち合わせには時間の枠がある**【人間】：回数ではなく、ゲームの中の時計で区切る。初回打ち合わせは90分の枠。画面の上に小さな時計（「14:00〜15:30　いま14:40」）を出す
     - 時計の進み方（エンジン）：担当者の質問と答えの1往復ごとに、答えの長さに応じて3〜8分進む。選択肢を押すだけなら短く、長い自由入力や脱線（同じ段で何往復もする）は長く進む
     - ふつうに聞かれたことに答えていけば、6段（0-5）がおよそ60〜70分で終わり、余裕をもって担当者が区切る
     - 残り15分になったら、担当者が「あと少しお時間がありますので、デザインのお好みだけ伺えますか」と、残りの段を急いでまとめる
     - 90分を超えたら、担当者が「たいへん申し訳ありませんが、次の予定が入っておりまして……。ここまで伺った内容を参考に、いったんご提案をまとめさせていただきますね」と言い、強制的に次の場面へ。聞けなかった段は「聞かれなかった要望」として台帳に残す（見落としの種）
     - 2社目、設計申込のあとの打ち合わせ（17の調整）も同じ仕組みで枠を持つ（調整は120分など）
   - 担当者が返事を書いているあいだは「打ち合わせを終える」を押せないようにする（押せると、返事が宙に浮く）
   - **担当者の最初の発言は、アンケートを受けた返事から始める**【人間】：「ご記入ありがとうございます。おふたりは、冬も暖かくて、家事が回しやすいお家がご希望なのですね。」→ そのあとで最初の質問。いきなり「平日の朝のことから順に聞かせてください」で始めない
   - アンケートの答えをClaudeに渡し、要約の1文を作らせる（数字は入れない）
9. **レポートに、守れなかった希望を入れる**【外部】
   - 「大切にしたこと」と「実現できたこと」を分ける。守れなかった希望と、どの分岐点で何を選べば守れたかを1行で

## P0　名前の入力と、ひとりプレイ【人間】

15. **夫婦の名前をプレイヤーが入力する**
    - いまは「かず」「ゆう」が初期値として入力欄に残っている。**入力欄の初期値は空にし、薄いグレーの見本の文字は「ニックネーム」だけ**にする【人間】
    - 入力がなければ「夫」「妻」と表示する【人間】。「かず」「ゆう」は内部の1人目・2人目の呼び名としてだけ残し、画面・会話・レポート・Claudeへのプロンプトの見本には一切出さない（プロンプトの例文に残っていると、AIの発言に混ざる）
    - 色と形（1人目＝橙■、2人目＝空色●）は名前に関係なく固定。画面・付箋・会話・レポートのすべてで、入力した呼び名を使う
    - 入力欄の近くに「ニックネームで入力してください」と添える（本名を入れさせない）。呼び名は記録には残すが、ほかの用途に使わない
16. **ひとりプレイのとき、パートナーをAIにできる**
    - 遊び方の1枚目で「ふたりで遊ぶ（交互に入力）」「ひとりで遊ぶ（パートナーはAI）」を選ぶ。**審査員はひとりで遊ぶことが多いと考えられるので、初期値は「ひとりで遊ぶ」**。タイトルの「打ち合わせを終えた家族で、続きから遊ぶ」も、ひとりプレイで始める
    - パートナーのAIは Sonnet 5.5 にハーネスとロールを与える（Opus は費用に見合う差が出にくいので、まずは Sonnet。役割ごとに環境変数で切り替え可能にしておく）
    - ロール：家族の設定から作る人格（価値観、こだわり、口ぐせ）。プレイヤーとは違う希望を持ち、ときどき意見がぶつかる。全部を決めてしまわない
    - 出番：担当者が「奥様は？」「ご主人は？」とパートナーに聞いたときに答える／帰り道に「伝え忘れたこと、あった？」と聞く／ときどき感想や心配を一言
    - パートナーの発言から出た希望は、パートナーの色（■か●）の付箋になる
    - 発言は短く（2〜3文）。数字は言わない（金額や日数はエンジン）。会話の主導権はプレイヤーに残す
    - ふたりで遊ぶときは、いまの「話す人」の切り替えを使い、担当者の質問に合わせて自動で切り替える（IMPL_REVIEW_1 のA9）

## P0　設計担当との調整（面積・ゾーニング・予算を確定させる）【人間の案、Claudeが具体化】

17. **要望から間取りの骨組みと予算を出す役割を Opus 5.5 にし、予算超過からの調整を、その場の打ち合わせとして体験させる**
    - 置き場所：第一の分岐点で会社を決めたあと、**設計申込・詳細打ち合わせ**（第二の分岐点「なにを優先する？」の手前）。プラン提案の時点では2社とも「ラフな概算」を出し、ここで1社と深く詰める
    - 役割の分担（大原則「言葉はClaude、数字はコード」を守る）
      - Opus：要望の台帳から、部屋の一覧（用途・広さの段階・1階か2階か・隣り合わせたい部屋）と、形の仮定（総二階／部分二階／平屋に近い、屋根の形）を組む。広さは「4.5畳／6畳／8畳…」のような**決まった選択肢から選ぶ**だけで、面積や金額の数字は作らない
      - エンジン：部屋の一覧から延床・1階と2階の床面積・建築面積を出し、建蔽率・容積率を判定し、形の係数（基礎と屋根は建築面積、外壁は外周の長さで効く）で見積と月々の返済を出す
      - Opus はツール呼び出しでエンジンに仮計算させ、結果を見て組み直す（読み替え → 仮計算 → 条件 → 承認 → 確定、の取引と同じ流れ）
    - 体験の流れ
      1. 担当者「いただいた要望を全部入れると、こうなります」→ ゾーニング図（1階・2階の部屋の塊を、コードで描く）と、延床・総額・月々・希望との違い（P0の1）
      2. 多くの場合は予算や建蔽率を超える。担当者が調整の案を2〜3つ出す（例：2階を広げて総二階に近づける＝基礎と屋根が減って安くなる／客間を和室コーナーに縮める／収納をまとめる）。案ごとに、エンジンが出した差額と、暮らしで何が変わるかを1行で
      3. プレイヤーは案を選ぶか、自由に書く（「書斎はいらない」「子ども部屋は将来仕切る」など）。そのたびにゾーニング図と金額が動く
      4. 「この間取りの骨組みと予算で設計を進めます」で確定 → 第二の分岐点へ。第二の分岐点の2択は、この調整の中で残った対立（例：広さを守る／総二階に寄せて予算を守る）から作る
    - 調整の回数は最大3回。超えたら担当者が「いったん持ち帰って整理しましょう」とまとめ、いちばん近い案で確定する
    - 待ち時間：Opus の応答中は、ゾーニング図の骨組み（読み込み中の形）と、担当者の「図面に落としています…」を出す。初回の案は、帰り道の場面のあいだに先に計算を始めておく
    - 選ばなかった世界線の家も、同じエンジンで延床と形を持つ（家の絵の大きさと形に反映する）
    - **モデルの分担**【人間】
      - 初回打ち合わせなどの会話のキャッチボール：Sonnet 5.5（返事は流し出して表示し、待たせない）
      - 提案書づくり（要望から部屋の構成・ゾーニング・形の仮定を組み、エンジンで見積を出す）：Opus 5.5
      - 見積と提案を会話で直すとき：プレイヤーが頼んだ直後に、担当者が「少し考えてみますね…」「図面に落としてみます」とすぐ返し（Sonnetか決まった文で即時）、**裏でOpusに修正案を作らせる**。実際の打ち合わせでも時間のかかる作業なので、待ち時間を演出にする。待つあいだはゾーニング図の骨組みが少しずつ描き変わる表示。そのあいだもプレイヤーはSNS・自分のAI・パートナーとの会話ができる。できたら担当者が「お待たせしました。こうしてみました」と出す
      - 修正案が一定時間（目安40秒）を超えたら、担当者が「次回までに整理してお持ちします」と引き取り、工程を1つ進めた次の場面で出す（待たせ続けない）
    - モデル：提案書づくりの役割（`PLANNER_MODEL`）だけ Opus 5.5。環境変数で Sonnet に切り替えられるようにする。1プレイあたりの呼び出し回数とトークン数を記録し、デモ前に費用を確かめる
    - エンジンへの追加：部屋の広さの段階の表、廊下・階段の割り増し、形の係数、建蔽率による上限。P0の1の「30坪に縮小」も、この仕組みで扱う
