# 流れ v3：提案＝契約までを、とんとん拍子の4つの分岐点で

作成：2026-11-05 03:15。発案元：流れの骨格（提案と見積を先に出し、本体を確定させてから契約。設備決め・ショールームはあきらめる。理由を聞くのはやめる）【人間】、分岐点への割り付けと細部【Claude】。
Claude Code へ：IMPL_REVIEW_2 の17（設計申込のあとにOpusが間取りを出して調整する場面）と、工程の12段階は、このファイルで置き換える。HEARING_v2（アンケート〜帰り道）はそのまま。

## 1. なぜ変えるか【人間】
- いまは「2社が概算を出して設計申込 → そのあとOpusが長考して間取りが出て、また選ぶ → 契約に向けて金額調整」になっていて、未経験者には意味がわからない
- 実際の家づくりに沿って、**見積の比較の前に、各社が大まかな間取りと面積の案を1つずつ出し、それに基づいて概算見積** → 家の本体を確定 → 設備などで少し増える → 見積の調整 → 契約、とする
- 時間がないので、**間取り・見積の提案から契約までを一続き**にし、未実装の設備決めとショールームはあきらめる。契約のあとはコーディネート・電気へ

## 2. 工程（上の線）を10段階に
見学・相談 → 初回打ち合わせ → **プラン提案・見積** → **契約** → 色決め・電気 → 着工 → 上棟 → 施主検査 → 引渡し → 1年後
- 「設計申込・詳細打ち合わせ」「ショールーム」を消す

## 3. 4つの分岐点の置き場所【Claude】
| 分岐点 | いつ | 何を選ぶ | 選んだあと |
|---|---|---|---|
| 第一：だれと建てる？ | プラン提案・見積の場面。2社の案が並んだとき | 2社のどちらか（各社の案＝間取りの骨組み・延床・立体・概算見積） | 選んだ会社と、そのまま本体の確定へ |
| 第二：なにを優先する？ | 直後（同じ打ち合わせの中） | 予算と広さの調整の2案（例：広さを守る／総二階に寄せて予算を守る）。自由回答も可 | **家の本体が確定**（延床・形・屋根） |
| 第三：いくらまでかける？ | 直後（契約の前の最終見積） | 契約に入れる範囲（例：外構まで仕上げる／外構は最小限で契約、窓のガラスを上げる／標準のまま）。自由回答も可 | **契約**（土地の契約の期限、ローン特約もここで） |
| 第四：どう仕上げる？ | 契約のあと、色決め（**色を選び終えて確定したあと**） | 色決めの結果から自動で決まる（下の3.5） | 電気の確認（P4-b、伝え漏れの見せ場）→ 着工の早送りへ |
- 第一〜第三は、短いつなぎ（「翌週、提案の日」「そのまま、予算の相談へ」「契約の前に、最終のお見積りです」）で**続けて**出す。それぞれ分岐点の儀式（ACCEPTANCE の2）
### 3.5 第四の分岐点は、色決めのあとに自動で出す【人間】
- いまは第四の分岐点の札が、色決めの画面より前に出て唐突。順番を逆にする
- 流れ：色決めの画面（P4-a）で、外壁・床・内壁の色と素材を楽しく選ぶ →「この仕上げで確定」→ 第四の分岐点の札「標準のまま」「グレードアップ」が**自動で出て**、プレイヤーの選んだ内容に合うほうが**自動で選ばれる**（標準の範囲だけなら「標準のまま」、1つでも上げていれば「グレードアップ」。差額はエンジン）→ もう一方は選ばれなかった世界線へ飛び、世界が15に増える → 電気の打ち合わせへ
- 札を押させない（選んだのは色決めの中なので、ここは結果を見せる演出）。儀式（暗転・札・飛ぶ・帯）は第一〜第三と同じだが短く（全体で3秒ほど）
- 帯の言葉：「第四の分岐点：グレードアップして仕上げた」など

- 世界線は第一のあと1、第二のあと3、第三のあと7、第四のあと15（いまのまま）

## 4. 提案の作り方（Opusの待ち時間を、物語の時間で隠す）【Claude】
- 帰り道（2社目の打ち合わせのあと）で、**2社分の提案を裏で同時に作り始める**（PLANNER＝Opus。要望の全体の記憶から、各社の性格で間取りの骨組み・形・屋根を組み、エンジンで延床・建蔽率・概算見積を出す）
- 同時に、第二の分岐点に使う**調整の2案**も各社ぶん先に作っておく（選ばれた会社の分を使う）
- 画面は「2週間後——提案の日」の帯（2〜3秒）。それでも間に合わなければ、骨組みの表示と担当者の「図面を広げますね」で数秒待つ
- 提案の画面：左右に2社。各社に①間取りの骨組み（1階・2階の部屋の塊）②延床と形（「35坪・総二階・片流れ」）③立体（その案の形と屋根で描く）④概算見積（その会社の見せ方：A本体価格／B本体＋オプション／C総額…）⑤希望との違い
- 屋根の形は、要望の記憶（アンケートと打ち合わせで決めたこと）を優先する。会社が別の形を勧めるときは、案の説明に理由を1行（勝手に変えない）
- 「34坪・総二階の案」のような決まった文を、どの会社にも出さない。各社の案の値から

## 5. 立体の絵【人間】
- 立体は、エンジンが持っている各社の条件と要望（延床、形、屋根、外構、選んだ仕上げ）を反映して描く。2社の比較では、各社の形の違いが見えること
- 2社を見分けやすくするため、提案の段階の外壁の色は会社で変える（仮の色）
- 色決め（第四）でプレイヤーが選んだあとは、**選んだ外壁・屋根・床の色を正確に反映した絵**を必ず出す（引渡し・1年後・レポートの水彩も同じデータから）

## 6. 理由を聞くのをやめる【人間】
- 各分岐点のあとの、パートナーの「どうしてそっちにしたの？」と理由の入力欄を、**すべて削除**する
- 経緯【Claude】：これは人間の指示ではなく、Claudeが IMPL_REVIEW_1 のA6で「レポートの理由が空になる対策」として提案し、IMPL_REVIEW_2 の16で【人間】の見出しの下に書いてしまったもの。発案元の誤り
- レポートの「あのとき守ろうとしたもの」は、聞かずに作る：選んだ札の中身、自由回答の言葉、アンケートの答え（とくに「いちばん大事」）、打ち合わせの発言から、エンジンが根拠を選び、Claudeが1文にする
- ACCEPTANCE の2の「パートナーの『どうしてそっちにしたの？』」と「理由の入力」の行は消す
