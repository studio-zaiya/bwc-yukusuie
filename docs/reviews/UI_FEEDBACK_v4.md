## 1. 決まったこと【人間】

### 共通
- **人間の自由入力欄は3行ほどに広げる。** 「SNSを見る」「自分のAIに聞く」のボタンは、自由入力欄の**下**に置く（主役ではなくフレーバー）。L1、ヒアリングのチャット、P4-b のすべてで同じ
- 金額の札は「総額（土地＋建物）」と「借入」、下に小さく「自己資金」（BRIEFの2.5のとおり）
- 「いま起きたこと」の帯には、「Claude」「エンジン」などの仕組みの名前を出さない。**起こった変化だけ**を出す。仕組みの説明は、動画のテロップで補う

### 締め
- E-A（design/v3/ending/E-A.html）で進める

### 来場者アンケートとヒアリング
- 4社それぞれにアンケートを書く面倒は再現しない
- **最初に訪問した1社で**、アンケート → ヒアリングを、タブ切り替えなしで完結させる
- 2社目以降は「前の会社と同じ要望を、アンケートと面談で伝えた」と注記したうえで、その会社の個性に応じて、担当者が質問や助言をしてくる。プレイヤーはそれに追加で答える
- **各社の見積・提案書を見比べる場面**：上にタブ（4社）、左に見積、右に提案内容と、簡単なゾーニングかパースふうのポンチ絵

### 担当者のアバター
- 4人のうち半分を女性にする
- P4-a のコーディネーターも、男性と女性の2種類を作り、ランダムで出し分ける

### 電気の打ち合わせ（P4-b）
- 要素はおおむね今の見本のまま
- 「この内容でOK」の下に、要望の候補をタグクラウドふうに並べる（例：間接照明、調光、コンセント／スイッチを増やしたい、照明を施主支給、太陽光・蓄電池、エアコンを施主支給、エアコンを隠したい、リモートワークに対応してほしい、トグルスイッチ）
- SNS と自分のAIは、この場面では固定の「おすすめ」を返してよい（中には「もう無理です」「できません」になるものも混ぜる）

### 入口
- チャットに入力していくと、付箋がリアルタイムのアニメーションで生まれていく
- スマホ連携はBRIEFの方針どおり

### レポート
- **1ページ目は表紙**：ロゴとシンボルマークを中央に大きく。動画の「手渡す」場面で、遠目にも何の紙かわかるように
- 今回のわが家をひとことで表す**タイトル**を付ける（住宅会社のプレゼンのタイトルのように、耳ざわりと字面のよいもの。例：「性能とコストのベストバランス。」「間取りは、メリハリ。」「断熱より、自然素材。」「ほぼ平屋のコンパクトプレミアム。」）
- 家の**パース画（水彩ふう）**を冒頭に入れる。もらってうれしいプレゼンシートにする
- 3ページ目の各世界線にも同じ調子の呼び名を付け、1行は「呼び名＋教訓：一言二言」にする
- 3ページ目上段のピックアップは残す
- 再生用のコードは印刷版（PDF）から外し、画面版に「再生」ボタンを付ける
- 画面版もおおむね同じ構成

### 通しの画面

## 2. Claudeの提案（★確認待ち。返事が来るまでは、この案で進めてよい）

### 2-1. 家の絵の密度の段階【人間の案を、手順に割り当てたもの】
| 手順 | 家の絵 |
|---|---|
| 初回打ち合わせ（要望の段階） | 1階が大きく2階が小さい、半透明の箱。要望から計算した面積で大きさが変わる。敷地からはみ出すと、はみ出した部分を淡い斜線で示す |
| プラン提案・見積（会社選び） | 4社それぞれのデザインの立体（屋根の形・窓・外壁の調子が違う）。見比べのタブと連動 |
| 第一の分岐点で会社を決める | 選んだ会社の案を、点線（細線）で描く |
| 設計申込・詳細打ち合わせ | 第二の分岐点の結果で、ボリュームと屋根の形が確定（細線のまま） |
| コーディネート | 選んだ外壁の色を、見本として面に薄く載せる |
| 申請・着工 → 上棟 → 施主検査 | 基礎 → 軸組 → 白い面 → 色の付いた面、の順に立ち上がる |
| 引渡し | 完成（W4の切り絵へ白いフェードでつなぐ） |

### 2-2. S7 →「そして1年後……」のトランジション
- 案A（推奨）：カメラが家から空へ引き上がり、空の色と木の葉が、夏 → 秋 → 冬 → 春と4秒で移り変わってから、1年後の家へ降りる。夜は通らない
- 案B：家の前の木が早回しで、若葉 → 紅葉 → 雪 → 花と変わる（定点）
- どちらも、最後に「1年後」の札を一瞬出す

### 2-3. S8〜S10 の流れ（認知の負荷を下げる）
1. **S8a 1年後のわが家（リザルト）**：自分の家のアップ。H8のような暮らし（洗濯物、庭、うさぎ）と、選択の結果（砂利のままの玄関、暖かい窓辺など）が絵に出る。ひとことの出来事を2〜3個
2. ボタン「16の区画を見る」→ **S8b 16区画**：区画を押すとその世界のカード（呼び名、教訓、総額、冬の朝、ゆとり）と「この世界を再生する」
3. ボタン「レポートを受け取る」→ **レポート（画面版）**：タブで「わが家」「選ばれなかった世界線」「それぞれの事情と見積の透視」。右上に「印刷用（PDF）」
4. **終わりの画面**：お礼、「もう一度遊ぶ」（同じ家族で別の選択／別の家族で）、「16の世界をAIにまかせて見る」（1回遊ぶと開く）、注記、Built with Claude

動画では S8b（16区画）を主に使い、S8a は一瞬見せる

### 2-4. レポートの分析（タイプ分け・レーダー・夫婦の傾向）とAPIの費用
- **タイプ分けはしない。** 16タイプのような固定の分類は「占い」に見えやすく、本作の主張（正解を決めない）ともぶつかる。また、会社側の別プロジェクトの型と混ざらないよう、そちらの分類や言葉は流用しない
- **レーダー図は、コードで出す（APIの費用はゼロ）**：エンジンの状態と決断の記憶から5軸を数える。例：暖かさ・性能／広さ・間取り／デザイン・素材／家計のゆとり／時間と手間。07とピックアップの世界を重ねて描く
- **夫婦の傾向も、数えるのはコード**：付箋の数を、かず■・ゆう●ごとに5軸へ振り分ける。言葉にする部分（2〜3文）だけをClaudeに書かせる
- **タイトルと世界線の呼び名、教訓**：レポート用の1回の呼び出し（上位モデル）でまとめて作る。コードで文字数（タイトル16字以内、教訓は20字前後）と禁止語を確かめ、外れたら1回だけ作り直す。それでもだめなら、手で用意した呼び名の候補（30個程度）から選ぶ
- **パース画（水彩ふう）**：画像生成は使わない方針なので、試作 W1（`prototypes/completion/W1-watercolor/`）の水彩の描き方を、家の状態のJSONから描く
- **費用の見込み**：1プレイの呼び出しは25回前後、入力の合計は数万トークン程度。レポートの呼び出しを増やしても1回分で、16の担当者の一言は安いモデルで1回に並列でまとめる。正確な金額は、実装時に料金表で確かめて devlog に書く

### 2-5. S6 のハプニング
- **入れる**：前の工程でフラグが立ったものだけ（伝え漏れ、確認不足、会社の管理の甘さ）。トラブル目録の「種がまかれる工程 → 芽が出る工程」に従う
- **余裕があれば**：本当の偶然（悪天候、近隣の声など）はフレーバーとして1つまで

### 2-6. S7 の写真保存
- 静止画になった時点で、canvas から画像を書き出して保存する。家族の名前や日付を、写真の隅に小さく入れられるとうれしい（入れる場合も、個人名は入力されたニックネームだけ）
