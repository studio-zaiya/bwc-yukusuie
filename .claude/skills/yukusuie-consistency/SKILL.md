# ゆくすいえ 一貫性の監査

目的【人間】：大げさな言葉を後から語り直すことではない。動画のコピーや説明で約束したことを、実機の側でも担保し、提出に向けたラップアップに入ること。
基準は `docs/PROMISE_LEDGER.md`（約束の表）。表にない約束を見つけたら、表に足す。

## 0. 準備
- 最新の材料を集める：動画の場面のHTML（`video/scenes/` の文字）、`video/VIDEO_PLAN.md` の構成、ナレーション原稿・字幕（あれば）、`out/SUBMISSION_FORM_DRAFT.md`、`README.md`
- 実機は**ふつうに遊んだ道**（タイトル →「家づくりを体験する」→ アンケートと打ち合わせ → 提案の日 → 第一〜第四の分岐点 → 電気 → 引渡し → 1年後 → レポート）を、ひとりプレイで通す。再生モードで同じ状況を再現し、各場面のスクリーンショットを `out/consistency/` に残す（webapp-testing スキルがあれば使う）

## 1. 約束 → 実機（動画と説明で言ったことが、実機で起きるか）
表の各行について：
1. その約束を証明する画面に、実際にたどり着けるか（ふつうに遊んだ道の上か、寄り道が要るか）
2. 画面で、約束の言葉どおりのことが起きているか（「伝えたのに違う」なら、伝えた根拠と、違っていたことの両方が画面に出るか）
3. 数字（総額、年収の何倍、16、1→3→7→15）が、動画・説明・実機でそろっているか
4. 言葉づかいがそろっているか（分岐点の名前、「選ばれなかった世界線」「決断の履歴を見る」、キャッチ、注記の文）
状態を ○／△／×／？ で埋め、△と×には「どの画面で、何が足りないか」を1行で書く。

## 2. 実機 → 約束（実機の見せ場が、動画と説明で語られているか）
- 実機にあるのに、動画にも説明にも出てこない見せ場を拾う（表の4）。言うべきか、言わなくてよいかの候補を出す（決めるのは人間）
- 実機から消えた・名前が変わった機能を、動画や説明がまだ言っていないか（README の古い記述など）

## 2.5 レポートと、プレイの一貫性
レポートは、プレイの結果を「本物の打ち合わせに持っていく紙」にしたもの。動画の締め（手渡し）と前振り⑧（あいだをつなぐ）の証明でもある。基準は `docs/REPORT_v2.md`。
- **数字**：総額・借入・月々・引渡しの日・冬の朝・家計のゆとりが、1年後の16区画のカードと**同じ状態**から出ているか（例：カード5,078万円とレポート5,158万円のずれは×）。金額の書き方がそろっているか
- **絵**：表紙の水彩と間取りの骨組みが、わが家のデータ（選んだ会社の案の形・屋根・延床、色決めで選んだ色、外構）と一致するか
- **言葉の根拠**：「守ろうとしたもの」「先に伝えておきたいこと」「ふたりの意見が分かれたこと」の各行が、アンケート・自由回答・打ち合わせの発言・選んだ札のどれかに根拠を持つか。プレイヤーが言っていない理由や気持ちを作っていないか。見出しと本文が食い違っていないか
- **守れなかった希望**：アンケートの希望の上限（総額・月々）と「いちばん大事」と答えたことの結果が、正直に書かれているか。守れた道（いちばん近い世界）が、実際にある世界の値から書かれているか
- **選ばなかった世界線**：載せた世界の総額・出来事・分岐が、16区画のカードと一致するか。「選択の差」と「出来事の差」が分かれているか
- **約束の表との対応**：レポートの見出し（「悩んだら、何を優先するか」「先に伝えておきたいこと」など）が、提出文・README・動画で言っている言葉と一致するか。キャッチ「16回目の、マイホームへ。」が入っているか
- **誠実さ**：「失敗でした」と判定しない。担当者や会社を貶めない。レポートの中に、仕組みの名前（Claude、エンジン）を出さない

## 3. 直す側の判断（候補を出すだけ。決めるのは人間）
- **文を直す**ほうがよいとき：実機の作りのほうが新しく、よくなっている（例：自由入力の画面 → アンケートと会話）
- **実機を直す**ほうがよいとき：動画の中心の約束（前振り⑥「全部伝えたのに、なぜか違う」、⑧「あいだをつなぐAI」など）が、実機で弱い・ふつうに遊んだ道の上にない
- 提出直前は、実機の大きな作り直しより、文の修正を優先する。ただし動画の中心の約束が実機にないままは不可

## 4. 守ること
- 実機で起きないことを、動画や説明で言わない（誇張しない）。動画の実機の場面は、期間中に作った実機の録画だけ
- 直す文は、CLAUDE.md の決まり（禁止の言い回し、個人名・勤務先を出さない、仕組みの名前を画面に出さない）を守る
- 発案元を区別する：言葉の修正案はClaudeの案として出し、人間の言葉として書かない

## 5. 出力の形
1. 約束の表（状態を埋めたもの）
2. レポートの照合（ページごと：数字・絵・言葉の根拠・守れなかった希望・選ばなかった世界線）
3. ×と△のうち、**動画の中心の約束**にかかわるもの（上から重い順、最大5つ）：どの約束／実機で何が足りないか／直す側の候補（実機か文か）と、その理由1行
4. 文の修正案（README、提出文、字幕）：直す前と後を並べる
5. 実機にあるのに言っていない見せ場：言う候補と、言わない理由
6. 次に確かめること（人間が見て決める点）
