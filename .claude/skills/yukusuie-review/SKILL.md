# ゆくすいえ 攻めのレビュー

ルール違反の点検ではなく（それは `yukusuie-audit`）、**見た人・遊んだ人に何が残るか**を厳しく問う。
いつもどおり、複数の立場から辛口でレビューしてから、統合した直す順番を出す。褒めるのは、残すべき理由があるときだけ。
できれば、実装した本人ではないサブエージェントで、立場ごとに分けて実行する。

## 0. 準備
1. `CLAUDE.md`、`docs/handoff.md`、`docs/UI_FEEDBACK_v4.md`、最新の `docs/IMPL_REVIEW_*.md` を読む。**人間が決めたこと（【人間】）は覆さない。** 変えたほうがよいと思ったら、提案として【Claude】と区別して書く
2. 対象を、実際に動かして見る
   - アプリ：Playwright で最初から最後まで1回通す。各画面を 1920×1080 で撮る。待ち時間も計る
   - 動画：書き出した mp4 を、1秒ごとのコマと字幕の一覧にして見る。音声がなければ、画面と字幕だけで評価する
3. 審査の配点（参考。原典で要確認）：インパクト30／デモ25／Claudeの使い方25／深さと完成度20。決勝は動画を再生して約2分の講評

## 1. 立場ごとのレビュー（少なくとも4つ）
それぞれ「最初の10秒で何がわかるか」「いちばん心が動いた瞬間」「いちばん冷めた瞬間」「何が足りないか」を答える。

1. **決勝の審査員**（3分の動画を1回だけ見る。家づくりに詳しくない）
   - 何をする作品か、10秒でわかるか。何がすごいのかを、見終わって一言で言えるか
   - 「凝った住宅相談のチャットボット」に見えていないか
   - 「これまでできなかった何が、これで可能になったか」が証明されているか
2. **初めて家を建てる共働きの夫婦**（実際に遊ぶ）
   - 入力したくなるか。自分の言葉が、家と世界に反映されたと感じるか
   - 迷子にならないか（何をすればいいか、いまどこか、あとどれくらいか）
   - 1年後とレポートで「次はこうしよう」と思えるか。持ち帰りたい紙か
3. **住宅会社の営業・設計者**（実務のプロとして見る）
   - 手順、時期、金額の感覚、担当者のふるまいが「あるある」として本物か
   - どの会社の型も、魅力と弱点が公平に描かれているか。特定の型が正解に見えていないか
4. **ゲームとUIが好きな人**
   - 画面のどこを見ればいいか、一目でわかるか。主役（家）とフレーバー（SNS・自分のAI）の強弱
   - テンポ。待ち時間の扱い。演出のメリハリ。絵柄の一貫性
5. **AIに詳しい技術者**（必要なら）
   - Claudeが文章を返しているだけか、Claudeの解釈がゲームの状態を変えているか
   - 処理の見せ方は実データか。誇張していないか

## 2. 論理の破綻と不自然さの点検
立場とは別に、次を必ず確かめる。
- 時系列（手続きの順番、期限の札、季節）が実務とずれていないか
- まだ決まっていないことが、決まったように出ていないか
- 名前・番号・宛先・記録が、途中で変わったり混ざったりしていないか
- 選択肢が実質1つになっていないか（片方だけ上限を超える、片方だけ明らかに得、など）
- 会社名や価格だけで、答えが自明になっていないか
- 同じ概念の言い換えの繰り返し、締めが何度も来る構成になっていないか
- 動画で見せた4つの分岐点と、実際のプレイの分岐点が一致しているか
- 前の工程の出来事が、後の工程で回収されているか（伝え漏れ → 電気の打ち合わせ、など）

## 3. これまでのレビューから学んだこと（毎回の基準）
- **証明の順番**：驚かせる → 理由を一言 → 実機で証明 → 深さ。説明から始めない
- **見せ場は因果**：一つの答えで、家と世界線が目の前で変わること。変化が画面上で起きなければ、チャットボットに見える
- **画面の死んだ場所**：大きな余白や動かない絵があると、視線は文字の欄にだけ行く
- **読めない量は、ないのと同じ**：1秒に十数字以上を読ませない。字幕は文字数÷4秒
- **くどさ**：同じ概念を言い換えて繰り返しても、説得力は増えない。直し方は言い換えではなく削除
- **締めは1回**：素材を流用すると、それぞれの起承転結が連結されて締めが何度も来る
- **数字の基準をそろえる**：建物だけの見積と、土地込みの借入を並べると、計算の誤りに見える
- **認知の混乱を招く言葉を避ける**：3分の中で、数え方の例外を持ち込まない
- **仕組みの名前を画面に出さない**：仕組みは動画のテロップで語る。画面は体験に徹する
- **絵柄の混在**：試作をつなぐと絵柄がばらつく。どれが本物の画面かを迷わせない
- **事前に説明しない**：起きることの予告やヒントは出さない。操作の説明は出してよい
- **公平さ**：会社と人を貶めない。偏りは、選択肢の数字やその場の情報の出し方から生まれる
- **持ち帰る価値**：入口（自由に何でも伝えられる）と出口（もらってうれしいレポート）に、いちばん力を注ぐ

## 4. 出力の形
1. 立場ごとのレビュー（各5〜8行。辛口で具体的に。画面名と秒数や状態を添える）
2. 論理の破綻と不自然さの一覧
3. **統合した直す順番**（上から5〜10件）

| 順 | 何を | なぜ（どの配点に効くか） | どう直すか | 手間（小・中・大） |
|---|---|---|---|---|

4. 残すべきもの（3つまで。理由つき）
5. 人間に決めてほしいこと（自分で決めずに、`docs/questions.md` に積む）

文体は日本語。断定しすぎず、根拠（どの画面のどこで、何が起きたか）を必ず添える。ほかの製品やAIツールの名前は出さない。
