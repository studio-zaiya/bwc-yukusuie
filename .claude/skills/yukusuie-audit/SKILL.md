# ゆくすいえ 守りの監査

作品のルールと事実に反していないかを、機械的に、漏れなく確かめる。面白さの評価はしない（それは `yukusuie-review` の役割）。
できれば、実装した本人ではないサブエージェントで実行する（作り手の思い込みを避けるため）。

## 0. 準備
1. `CLAUDE.md`、`docs/handoff.md`、`docs/CLAUDE_CODE_BRIEF.md`、`docs/UI_FEEDBACK_v4.md`、最新の `docs/IMPL_REVIEW_*.md` を読む。**人間が決めたこと（【人間】）が最優先**
2. 対象を決める：変更されたファイル（`git diff --name-only` で前回の監査以降）、または指定された画面・動画
3. 画面を点検するときは、Playwright で主要な状態を 1920×1080 で撮る（`?rec=1` でも撮る）

## 1. 自動で確かめること（コマンドで）
次を検索し、ヒットした箇所をすべて一覧にする。`prototypes/` と `design/v2/` は版の記録なので対象外（ただし本番や動画に流用していないかは確かめる）。

```bash
# 個人・実在の名前と、人間が指定した使わない語（一覧は公開しない：.claude/local/private-words.txt。リポジトリに入れない）
rg -n -F -f .claude/local/private-words.txt --glob '!prototypes/**' --glob '!design/v2/**' --glob '!.claude/local/**'
# 禁止の言い回し（人間の明示の指示がない限り禁止）
rg -n "17本目|17番目|17の世界|2択じゃなく|16に納まら|16通りより|未来は、16|正解の家より" --glob '!prototypes/**' --glob '!design/v2/**'
# ギリシャ文字
rg -n "[Α-Ωα-ω]" --glob '!prototypes/**' --glob '!design/v2/**'
# 仕組みの名前を画面に出していないか（画面の文言のみ。コードのコメントや変数名は可）
rg -n "エンジンの値|エンジン：|Claude：|Claudeが" src/ --glob '*.html' --glob '*.js'
# 赤・絵文字
rg -n "#[Ff]{2}0000|#[Dd]\w{1}0000|red\b" src/
rg -nP "[\x{1F300}-\x{1FAFF}\x{2600}-\x{27BF}]" src/
# APIキーが画面側に出ていないか
rg -n "sk-ant-|ANTHROPIC_API_KEY" src/ --glob '!src/worker/**'
```

## 2. 目で確かめること（チェックリスト）

### 2-1. 公開物のルール【人間】
- [ ] 画面・README・コミット・動画に、作り手の個人名・ハンドル・勤務先・顔がない。呼び名は「人間」「演出家」
- [ ] 実在の会社名・人物名・SNS名・ロゴ・配色をまねていない（メッセージアプリやSNSは架空。緑の吹き出しなど既存のアプリを想起させる配色にしない）
- [ ] 住宅会社は Aハウス／Bハウス／Cデザイン／D工務店
- [ ] 注記の文が、ゲームの最初と動画の最後にある
- [ ] ゲーム内の出来事はすべて架空

### 2-2. 言葉【人間】
- [ ] 2択の外の答えに、特別扱いの言葉を付けていない
- [ ] 後悔している人、リフォーム、マンションを否定していない
- [ ] どの住宅会社も貶めていない（「最善を目指したが、こうなった」の温度）。担当者の本音は「それぞれの事情」の温度
- [ ] ラベルを付けすぎていない（「〇〇模型」のような説明の札を画面に書かない）
- [ ] 画面に「Claude」「エンジン」などの仕組みの名前を出していない（説明は動画のテロップで）
- [ ] 同じ概念を、言い回しを変えて繰り返していない
- [ ] 字幕は最低1.8秒、文字数÷4秒以上。1画面に読ませる量が多すぎない

### 2-3. デザインコード
- [ ] 紙 #FFFAF0、墨 #1E2B36（真っ黒なし）。かず＝橙 #E8701F・■、ゆう＝空色 #1C8DCC・●、第3の答え＝金の破線・◆
- [ ] 住宅会社に色を付けていない（墨の札＋形：A四角・B三角・C丸・D六角）
- [ ] 赤、絵文字、ネオン、粒子の爆発、暗い演出がない。増減を赤・緑で塗っていない
- [ ] フラット屋根に煙突がない
- [ ] 字形はヒラギノ系を優先（Hiragino Sans → BIZ UDPGothic → Zen Maru Gothic）
- [ ] ロゴはマークB＋E式の丸ゴシックの文字（日本語・英字とも）

### 2-4. 数字の出どころ【大原則】
- [ ] 金額・日数・面積・判定は、すべて `src/engine/` が出している。Claudeの出力に数字が入っていない（入っていたら、エンジンの値で置き換えているか）
- [ ] 金額は万円の整数で表示（内部の小数を表示しない）
- [ ] 金額の札は「総額（土地＋建物）」と「借入」、下に小さく「自己資金」。契約後は「土地＋契約金額＋増工」。基準の違う数字を並べていない
- [ ] 借入の上限の判定が、すべての選択肢で同じ規則
- [ ] エンジンのテスト（`node --test`）が通る

### 2-5. AIの見せ方の誠実さ
- [ ] Claudeの呼び出しが失敗したとき、決まり文句で成功したように見せていない（失敗は記録に残り、開発中は画面にわかる形で出る）
- [ ] 「いま起きたこと」の帯や処理の表示は、実際の呼び出しの記録から作っている（台本ではない）
- [ ] 動画の実機パートは、本物の呼び出しで遊んだ記録の再生か、実際の操作
- [ ] 「エージェント型」「並列」などは、実装が伴っているときだけ名乗っている
- [ ] 記録に、入力・出力の全文・モデル名・プロンプトの版が残っている

### 2-6. 家づくりの実務と論理
- [ ] 手順の順番が正しい（土地の契約 → ローン特約 → 決済。ローン特約の期限を、土地の契約前に出さない）
- [ ] まだ決まっていないこと（屋根の形、坪数、会社）を、決まったように表示していない
- [ ] 4つの分岐点の名前・順番・置き場所が、動画の前振りと一致（だれと建てる？／なにを優先する？／いくらまでかける？／どう仕上げる？。第三は契約前、第四は契約後のコーディネート）
- [ ] 選ばれなかった世界線は、1 → 3 → 7 → 15 と増える。第一の分岐の前は出さない
- [ ] プレイヤーの家の番号・名前が、途中で変わらない
- [ ] 会社ごとのチャットの記録が混ざらない。宛先（パートナー／担当者）が取り違えられていない
- [ ] 「伝えたのに入っていない」と「伝えていない」が区別されている

### 2-7. 開発記録（審査用）
- [ ] 期間中の作業だけがコミットされている。事前の調査メモがコミットされていない
- [ ] `docs/devlog.md` に今回の区切りの記録がある

## 3. 出力の形
次の表で返す。重さは P0（提出前に必ず直す）／P1（直したい）／P2（余裕があれば）。

| 重さ | 場所（ファイル:行、または画面と状態） | 問題 | 根拠（ルールの出どころ） | 直し方 |
|---|---|---|---|---|

最後に、P0の件数と、ルールの解釈に迷った点（人間に確かめること）を書く。自分で決めずに、`docs/questions.md` に積む。
